클로드 코드를 터미널(CLI)에서 쓸 때와 데스크톱 앱에서 쓸 때의 주요 차이는 다음과 같습니다.

## 1. 실행 방식
- **터미널**: `claude` 명령어로 셸(터미널 에뮬레이터, iTerm2, VS Code 통합 터미널 등)에서 직접 실행. 텍스트 기반 인터페이스.
- **데스크톱 앱(Mac/Windows)**: GUI 앱으로 실행. 채팅창, 파일 미리보기, 클릭 가능한 링크 등 시각적 UI 제공. 내부적으로는 동일한 엔진을 사용하지만 앱 화면 안에서 대화가 이루어짐.

## 2. 작업 폴더(작업 디렉터리) 지정 방식 — 핵심 차이
- **터미널**: 작업 폴더는 **명령어를 실행하는 현재 디렉터리(cwd)**로 자동 결정됩니다. 즉, 먼저 `cd /path/to/project` 로 이동한 뒤 그 디렉터리에서 `claude`를 실행하면, 그 폴더가 작업 디렉터리가 됩니다. 별도의 "폴더 선택" UI가 없고, 셸의 `cd` 명령이 곧 폴더 지정 방법입니다.
- **데스크톱 앱**: GUI에서 **프로젝트/폴더를 직접 선택하는 화면(파일 탐색기 다이얼로그 또는 "Open Folder" 버튼)**을 통해 작업 디렉터리를 지정합니다. 터미널처럼 셸의 현재 위치에 의존하지 않고, 앱이 별도로 어떤 폴더를 열지 물어봅니다. 여러 프로젝트를 앱 내에서 전환하며 열어둘 수도 있습니다.

## 3. 기타 차이
- **세션/창 관리**: 터미널은 각 세션이 하나의 셸 프로세스에 묶이지만, 데스크톱 앱은 여러 프로젝트 창/탭을 GUI에서 관리할 수 있습니다.
- **파일/이미지 미리보기**: 데스크톱 앱은 이미지, diff, 코드 등을 시각적으로 렌더링해서 보여주는 반면, 터미널은 텍스트/ANSI 출력 위주입니다.
- **확장/통합**: 터미널 버전은 셸 스크립트, 파이프(`|`), 다른 CLI 도구와 조합하기 쉽고, IDE 확장(VS Code, JetBrains)과도 연동됩니다. 데스크톱 앱은 독립 실행형 GUI 경험에 초점이 맞춰져 있습니다.

요약하면, 기능적으로는 같은 클로드 코드 엔진을 쓰지만, **터미널은 "cd로 이동한 현재 디렉터리"가 곧 작업 폴더**가 되고, **데스크톱 앱은 GUI에서 폴더를 명시적으로 선택**하는 방식이라는 점이 가장 실질적인 차이입니다.
