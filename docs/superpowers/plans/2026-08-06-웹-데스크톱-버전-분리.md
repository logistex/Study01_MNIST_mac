> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 Tkinter 손글씨 인식 앱을 `desktop_version/`으로 옮기고, 브라우저에서 도는 `web_version/`을 외부 라이브러리 없이 새로 만든다.

**Architecture:** 학습과 가중치 관리는 `desktop_version/`이 맡는다. 파이썬 스크립트가 `mnist_cnn.pt`를 float32 바이너리와 형상 JSON으로 내보내면, `web_version/`은 그 두 파일만 읽어 자바스크립트로 전처리와 순전파를 직접 수행한다. 웹 폴더에는 파이썬 의존성도 외부 라이브러리도 없다. 정확성은 파이썬이 만든 정답 데이터와 브라우저 결과를 대조하는 검증 페이지로 판정한다.

**Tech Stack:** Python 3.14 + PyTorch 2.13 + torchvision + Pillow (데스크톱), 순수 ES 모듈 자바스크립트 + Canvas 2D (웹). 빌드 도구 없음. npm 없음.

## Global Constraints

- **식별자와 주석을 모두 한글로 쓴다.** 파이썬과 자바스크립트 모두 해당한다. 함수, 변수, 상수 이름이 한글이다 (`손글씨분류모델`, `그리는중`, `붓굵기`). 예외는 셸 스크립트뿐이다.

- **기존 파이썬 네 파일(`model.py`, `train.py`, `preprocess.py`, `app.py`)은 한 글자도 고치지 않는다.** 이동만 한다.

- [ ] **Step 2: 내보내기 스크립트를 쓴다**

`TZ=Asia/Seoul date "+%Y-%m-%d %H:%M"` 을 실행해 얻은 값을 첫 줄 주석에 넣는다.

`desktop_version/가중치내보내기.py`:

```python
"""학습된 가중치를 웹 버전이 읽을 수 있는 형식으로 내보낸다.

웹 버전은 파이썬 없이 도는 정적 페이지라서 mnist_cnn.pt 를 직접 읽지 못한다.
그래서 텐서를 float32 바이너리 한 덩어리로 풀어 쓰고, 각 텐서의 이름과 형상은
별도의 JSON 에 적어 둔다. 자바스크립트는 JSON 을 보고 바이너리를 잘라 쓴다.

형상과 정규화 상수를 자바스크립트에 직접 적지 않는 이유는, 파이썬 쪽을 고쳤을 때
웹 쪽이 조용히 어긋나는 일을 막기 위해서다. 값의 출처는 언제나 파이썬이다.

실행: python3 가중치내보내기.py
"""
# 2026-08-06 18:02 KST 생성

import json
from pathlib import Path

import torch

from preprocess import 표준편차, 평균

이폴더 = Path(__file__).resolve().parent
모델파일 = 이폴더 / "mnist_cnn.pt"
웹폴더 = 이폴더.parent / "web_version"

# 자바스크립트가 이 순서대로 바이너리를 잘라 읽는다. 순서를 바꾸면 웹이 깨진다.
내보낼순서 = [
    "합성곱1.weight", "합성곱1.bias",
    "합성곱2.weight", "합성곱2.bias",
    "전결합1.weight", "전결합1.bias",
    "전결합2.weight", "전결합2.bias",
]


def 내보내기():
    if not 모델파일.exists():
        raise SystemExit(f"{모델파일} 이 없습니다. 먼저 python3 train.py 를 실행해 주세요.")

    상태 = torch.load(모델파일, map_location="cpu")

    빠진것 = [이름 for 이름 in 내보낼순서 if 이름 not in 상태]
    if 빠진것:
        raise SystemExit(f"가중치에 다음 텐서가 없습니다: {빠진것}")

    조각들 = []
    정보 = []
    for 이름 in 내보낼순서:
        텐서 = 상태[이름].detach().cpu().contiguous()
        정보.append({"이름": 이름, "형상": list(텐서.shape)})
        # 애플 실리콘은 리틀엔디언이지만, 바이트 순서를 명시해 두면 오해가 없다.
        조각들.append(텐서.numpy().astype("<f4").tobytes())
```

`web_version/모델.js`:

```javascript
// 2026-08-06 18:02 KST 생성
//
// 학습된 CNN 의 순전파를 자바스크립트로 직접 구현한다.
//
// 이 맥의 파이썬 3.14 에는 onnx 패키지 휠이 없어 ONNX 변환이 불가능하다.
// 다행히 모델이 작아서(파라미터 42만 개, 곱셈덧셈 430만 번) 직접 구현이
// 현실적이다. desktop_version/model.py 의 구조를 그대로 옮긴 것이므로,
// model.py 를 바꾸면 이 파일도 반드시 함께 바꿔야 한다.
//
// 드롭아웃은 예측 모드에서 항등이라 구현하지 않는다.

/** 가중치 바이너리와 형상 정보를 읽어 예측 준비를 마친 모델을 돌려준다. */
export async function 모델불러오기(기준경로 = ".") {
  const 정보응답 = await fetch(`${기준경로}/가중치정보.json`);
  if (!정보응답.ok) {
    throw new Error(`가중치정보.json 을 읽지 못했습니다 (${정보응답.status}).`);
  }
  const 정보 = await 정보응답.json();

  const 바이너리응답 = await fetch(`${기준경로}/가중치.bin`);
  if (!바이너리응답.ok) {
    throw new Error(`가중치.bin 을 읽지 못했습니다 (${바이너리응답.status}).`);
  }
  const 전체 = new Float32Array(await 바이너리응답.arrayBuffer());

  const 가중치 = {};
  let 위치 = 0;
  for (const 텐서 of 정보.텐서) {
    const 개수 = 텐서.형상.reduce((누적, 값) => 누적 * 값, 1);
    가중치[텐서.이름] = 전체.subarray(위치, 위치 + 개수);
    위치 += 개수;
  }
  if (위치 !== 전체.length) {
    throw new Error(`가중치 크기가 맞지 않습니다 (${위치} / ${전체.length}).`);
  }

  return { 가중치, 평균: 정보.평균, 표준편차: 정보.표준편차 };
}

/** 3x3 합성곱, 패딩 1, 스트라이드 1. 출력 크기는 입력과 같다. */
function 합성곱(입력, 입력채널, 크기, 가중치, 편향, 출력채널) {
  const 출력 = new Float32Array(출력채널 * 크기 * 크기);

  for (let 나감 = 0; 나감 < 출력채널; 나감++) {
    for (let 세로 = 0; 세로 < 크기; 세로++) {
      for (let 가로 = 0; 가로 < 크기; 가로++) {
        let 누적 = 편향[나감];

        for (let 들어옴 = 0; 들어옴 < 입력채널; 들어옴++) {
          const 입력바닥 = 들어옴 * 크기 * 크기;
          const 가중치바닥 = (나감 * 입력채널 + 들어옴) * 9;

          for (let 창세로 = 0; 창세로 < 3; 창세로++) {
            const 원세로 = 세로 + 창세로 - 1;
            if (원세로 < 0 || 원세로 >= 크기) continue;

            for (let 창가로 = 0; 창가로 < 3; 창가로++) {
              const 원가로 = 가로 + 창가로 - 1;
              if (원가로 < 0 || 원가로 >= 크기) continue;

              누적 += 입력[입력바닥 + 원세로 * 크기 + 원가로]
                    * 가중치[가중치바닥 + 창세로 * 3 + 창가로];
            }
          }
        }
        출력[(나감 * 크기 + 세로) * 크기 + 가로] = 누적;
      }
    }
  }
  return 출력;
}

/** 음수를 0으로 만든다. 입력 배열을 그 자리에서 고친다. */
function 렐루(값들) {
  for (let 자리 = 0; 자리 < 값들.length; 자리++) {
    if (값들[자리] < 0) 값들[자리] = 0;
  }
  return 값들;
}

/** 2x2 최댓값 풀링. 크기를 절반으로 줄인다. */
function 맥스풀링2(입력, 채널수, 크기) {
  const 새크기 = Math.floor(크기 / 2);
  const 출력 = new Float32Array(채널수 * 새크기 * 새크기);

  for (let 채널 = 0; 채널 < 채널수; 채널++) {
    const 입력바닥 = 채널 * 크기 * 크기;
    const 출력바닥 = 채널 * 새크기 * 새크기;

    for (let 세로 = 0; 세로 < 새크기; 세로++) {
      for (let 가로 = 0; 가로 < 새크기; 가로++) {
        const 왼위 = 입력바닥 + (세로 * 2) * 크기 + 가로 * 2;
        const 최댓값 = Math.max(
          입력[왼위], 입력[왼위 + 1],
          입력[왼위 + 크기], 입력[왼위 + 크기 + 1],
        );
        출력[출력바닥 + 세로 * 새크기 + 가로] = 최댓값;
      }
    }
  }
  return 출력;
}

/** 완전연결 층. 가중치는 [출력수, 입력수] 형상의 행 우선 배열이다. */
function 전결합(입력, 가중치, 편향, 입력수, 출력수) {
  const 출력 = new Float32Array(출력수);

  for (let 나감 = 0; 나감 < 출력수; 나감++) {
    let 누적 = 편향[나감];
    const 줄시작 = 나감 * 입력수;
    for (let 들어옴 = 0; 들어옴 < 입력수; 들어옴++) {
      누적 += 입력[들어옴] * 가중치[줄시작 + 들어옴];
    }
    출력[나감] = 누적;
  }
  return 출력;
}

/** 점수 10개를 확률로 바꾼다. 큰 값을 빼서 오버플로를 막는다. */
function 소프트맥스(점수) {
  const 최댓값 = Math.max(...점수);
  const 확률 = new Float32Array(점수.length);
  let 합 = 0;
  for (let 자리 = 0; 자리 < 점수.length; 자리++) {
    확률[자리] = Math.exp(점수[자리] - 최댓값);
    합 += 확률[자리];
  }
  for (let 자리 = 0; 자리 < 확률.length; 자리++) {
    확률[자리] /= 합;
  }
  return 확률;
}

/**
 * 정규화를 마친 28x28 입력(Float32Array 784개)을 받아
 * 숫자 0~9 에 대한 확률 10개를 돌려준다.
 */
export function 예측하기(입력, 모델) {
  if (입력.length !== 784) {
    throw new Error(`입력 길이가 784가 아닙니다 (${입력.length}).`);
  }
  const ㄱ = 모델.가중치;

  let 특징 = 합성곱(입력, 1, 28, ㄱ["합성곱1.weight"], ㄱ["합성곱1.bias"], 32);
  특징 = 맥스풀링2(렐루(특징), 32, 28);                       // 32x28x28 -> 32x14x14

  특징 = 합성곱(특징, 32, 14, ㄱ["합성곱2.weight"], ㄱ["합성곱2.bias"], 64);
  특징 = 맥스풀링2(렐루(특징), 64, 14);                       // 64x14x14 -> 64x7x7

  // 평탄화는 별도 작업이 필요 없다. 이미 [채널][세로][가로] 순으로 이어져 있어
  // 파이토치의 flatten 결과와 순서가 같다.
  const 숨은층 = 렐루(전결합(특징, ㄱ["전결합1.weight"], ㄱ["전결합1.bias"], 3136, 128));
  const 점수 = 전결합(숨은층, ㄱ["전결합2.weight"], ㄱ["전결합2.bias"], 128, 10);

  return 소프트맥스(점수);
}
```

```javascript
// 2026-08-06 18:02 KST 생성
//
// 캔버스에 그린 그림을 MNIST 형식으로 바꾸는 전처리.
// desktop_version/preprocess.py 를 자바스크립트로 옮긴 것이다.
//
// MNIST 이미지는 단순히 28x28 로 줄인 그림이 아니라 다음 규칙으로 만들어졌다.
//   1. 숫자가 없는 바깥 여백을 잘라낸다.
//   2. 가로세로 비율을 유지한 채 20x20 안에 들어가도록 줄인다.
//   3. 28x28 검은 배경 위에, 숫자의 무게중심이 한가운데에 오도록 붙인다.
// 셋 중 하나라도 빠지면 인식률이 뚝 떨어진다.
//
// 파이썬과 딱 한 곳이 다르다. PIL 의 LANCZOS 축소를 브라우저에서 똑같이
// 재현할 수 없어 면적 평균 축소를 직접 구현했다. 이 차이가 정확도에 영향을
// 주는지는 검증.html 로 판정한다.

/** 파이썬 round 와 같은 규칙(정확히 0.5 면 짝수 쪽)으로 반올림한다. */
function 파이썬반올림(값) {
  const 내림 = Math.floor(값);
  const 나머지 = 값 - 내림;
  if (나머지 > 0.5) return 내림 + 1;
  if (나머지 < 0.5) return 내림;
  return 내림 % 2 === 0 ? 내림 : 내림 + 1;
}

/**
 * Canvas 2D 의 ImageData 에서 밝기만 뽑는다.
 *
 * 캔버스에는 검은 배경에 흰 글씨만 그리므로 R, G, B 가 항상 같다.
 * 그래서 R 채널을 그대로 밝기로 쓴다.
 */
export function 밝기만뽑기(이미지자료) {
  const 화소수 = 이미지자료.width * 이미지자료.height;
  const 밝기 = new Float32Array(화소수);
  for (let 자리 = 0; 자리 < 화소수; 자리++) {
    밝기[자리] = 이미지자료.data[자리 * 4];
  }
  return 밝기;
}

/** 면적 평균으로 축소한다. 겹치는 넓이를 가중치로 삼는다. */
function 면적평균축소(밝기, 너비, 높이, 새너비, 새높이) {
  const 출력 = new Float32Array(새너비 * 새높이);
  const 가로비 = 너비 / 새너비;
  const 세로비 = 높이 / 새높이;

  for (let 새세로 = 0; 새세로 < 새높이; 새세로++) {
    const 위 = 새세로 * 세로비;
    const 아래 = (새세로 + 1) * 세로비;

    for (let 새가로 = 0; 새가로 < 새너비; 새가로++) {
      const 왼 = 새가로 * 가로비;
      const 오른 = (새가로 + 1) * 가로비;

      let 누적 = 0;
      let 넓이합 = 0;

      for (let 세로 = Math.floor(위); 세로 < Math.ceil(아래); 세로++) {
        const 세로겹침 = Math.min(아래, 세로 + 1) - Math.max(위, 세로);
        if (세로겹침 <= 0) continue;

        for (let 가로 = Math.floor(왼); 가로 < Math.ceil(오른); 가로++) {
          const 가로겹침 = Math.min(오른, 가로 + 1) - Math.max(왼, 가로);
          if (가로겹침 <= 0) continue;

          const 넓이 = 세로겹침 * 가로겹침;
          누적 += 밝기[세로 * 너비 + 가로] * 넓이;
          넓이합 += 넓이;
        }
      }
      출력[새세로 * 새너비 + 새가로] = 넓이합 > 0 ? 누적 / 넓이합 : 0;
    }
  }
  return 출력;
}

/**
 * 검은 배경에 흰 글씨로 그린 밝기 배열을 28x28 MNIST 형식으로 바꾼다.
 * 결과는 밝기 0~255 값을 담은 Float32Array(784) 이고,
 * 아무것도 그리지 않았으면 null 을 돌려준다.
 */
export function mnist형식으로변환(밝기, 너비, 높이) {
  // 1) 글씨가 있는 부분(밝은 화소)의 최소 사각형을 찾는다.
  let 윗줄 = 높이, 아랫줄 = -1, 왼쪽 = 너비, 오른쪽 = -1;
  for (let 세로 = 0; 세로 < 높이; 세로++) {
    for (let 가로 = 0; 가로 < 너비; 가로++) {
      if (밝기[세로 * 너비 + 가로] > 20) {
        if (세로 < 윗줄) 윗줄 = 세로;
        if (세로 > 아랫줄) 아랫줄 = 세로;
        if (가로 < 왼쪽) 왼쪽 = 가로;
        if (가로 > 오른쪽) 오른쪽 = 가로;
      }
    }
  }
  if (아랫줄 < 0) return null;

  const 자른너비 = 오른쪽 - 왼쪽 + 1;
  const 자른높이 = 아랫줄 - 윗줄 + 1;
  const 자른것 = new Float32Array(자른너비 * 자른높이);
  for (let 세로 = 0; 세로 < 자른높이; 세로++) {
    for (let 가로 = 0; 가로 < 자른너비; 가로++) {
      자른것[세로 * 자른너비 + 가로] = 밝기[(윗줄 + 세로) * 너비 + (왼쪽 + 가로)];
    }
  }

  // 2) 비율을 유지하며 긴 변이 20이 되도록 줄인다.
  const 비율 = 20.0 / Math.max(자른너비, 자른높이);
  const 새너비 = Math.max(1, 파이썬반올림(자른너비 * 비율));
  const 새높이 = Math.max(1, 파이썬반올림(자른높이 * 비율));
  const 줄인것 = 면적평균축소(자른것, 자른너비, 자른높이, 새너비, 새높이);

  // 3) 28x28 검은 배경 한가운데에 일단 붙인다.
  const 도화지 = new Float32Array(28 * 28);
  const 붙일가로 = Math.floor((28 - 새너비) / 2);
  const 붙일세로 = Math.floor((28 - 새높이) / 2);
  for (let 세로 = 0; 세로 < 새높이; 세로++) {
    for (let 가로 = 0; 가로 < 새너비; 가로++) {
      도화지[(붙일세로 + 세로) * 28 + (붙일가로 + 가로)] = 줄인것[세로 * 새너비 + 가로];
    }
  }

  // 4) 밝기를 무게로 삼아 무게중심을 계산하고, 중앙(13.5, 13.5)으로 옮긴다.
  let 전체무게 = 0;
  let 세로가중합 = 0;
  let 가로가중합 = 0;
  for (let 세로 = 0; 세로 < 28; 세로++) {
    for (let 가로 = 0; 가로 < 28; 가로++) {
      const 무게 = 도화지[세로 * 28 + 가로];
      전체무게 += 무게;
      세로가중합 += 세로 * 무게;
      가로가중합 += 가로 * 무게;
    }
  }
  if (전체무게 <= 0) return 도화지;

  const 옮길가로 = 파이썬반올림(13.5 - 가로가중합 / 전체무게);
  const 옮길세로 = 파이썬반올림(13.5 - 세로가중합 / 전체무게);
  if (옮길가로 === 0 && 옮길세로 === 0) return 도화지;

  const 옮긴것 = new Float32Array(28 * 28);
  for (let 세로 = 0; 세로 < 28; 세로++) {
    const 원세로 = 세로 - 옮길세로;
    if (원세로 < 0 || 원세로 >= 28) continue;
    for (let 가로 = 0; 가로 < 28; 가로++) {
      const 원가로 = 가로 - 옮길가로;
      if (원가로 < 0 || 원가로 >= 28) continue;
      옮긴것[세로 * 28 + 가로] = 도화지[원세로 * 28 + 원가로];
    }
  }
  return 옮긴것;
}

/** 학습 때 쓴 값으로 정규화해 모델 입력 형태로 만든다. */
export function 정규화(밝기, 평균, 표준편차) {
  const 입력 = new Float32Array(밝기.length);
  for (let 자리 = 0; 자리 < 밝기.length; 자리++) {
    입력[자리] = (밝기[자리] / 255 - 평균) / 표준편차;
  }
  return 입력;
}
```

````markdown
## 환경 제약 (중요)

이 맥의 제약 때문에 일반적인 구성과 다르다. "고치려" 들기 전에 확인할 것.

- **파이썬 3.14뿐이고 TensorFlow 는 3.14용 배포판이 없다.** 그래서 Keras 가 아니라 PyTorch(2.13)로 구현했다. Keras 로 바꾸려면 파이썬 3.12나 3.13을 따로 설치해야 한다.
- **onnx 패키지도 3.14용 휠이 없다.** free-threaded 빌드(`cp314t`)용만 있는데 이 맥의 파이썬은 GIL 이 켜진 일반 빌드다. 그래서 웹 버전은 ONNX 대신 가중치를 직접 내보내는 방식을 쓴다.
- **MNIST 자동 내려받기는 SSL 인증서 오류로 실패한다.** (`CERTIFICATE_VERIFY_FAILED`) 원본 `.gz` 4개를 `curl` 로 `data/MNIST/raw/` 에 직접 받아 두었고, `download=True` 는 파일이 이미 있으면 건너뛴다. 데이터를 지웠다면 `https://ossci-datasets.s3.amazonaws.com/mnist/` 에서 다시 받는다. 근본 해결은 `/Applications/Python 3.14/Install Certificates.command` 실행(관리자 권한 필요).
- 학습은 애플 실리콘 GPU(MPS)를 쓴다. 예측은 CPU 로 한다.

## 구조

네 파일이 하나의 사슬로 엮여 있다. 한 곳을 바꾸면 다른 곳도 같이 손봐야 한다.

- **`model.py`** — CNN 구조. `train.py` 와 `app.py` 가 **함께 임포트한다.** 구조를 바꾸면 `mnist_cnn.pt` 의 `state_dict` 와 어긋나므로 **반드시 재학습해야 한다.** 웹 버전의 `모델.js` 도 이 구조를 손으로 옮긴 것이라 함께 고쳐야 한다.
- **`train.py`** — 학습 전용. 데이터 적재, 학습 루프, 평가, 가중치 저장.
- **`preprocess.py`** — 캔버스 그림을 MNIST 형식으로 바꾸는 전처리. **이 프로젝트에서 가장 깨지기 쉬운 부분이다.**
- **`app.py`** — Tkinter GUI. 그리기, 전처리 호출, 예측, 결과 표시.

웹 버전을 위한 스크립트 둘이 더 있다.

- **`가중치내보내기.py`** — `mnist_cnn.pt` 를 `../web_version/가중치.bin` 과 `가중치정보.json` 으로 내보낸다. 학습을 다시 했다면 이것도 다시 돌려야 웹 버전이 새 가중치를 쓴다.
- **`검증데이터만들기.py`** — MNIST 테스트 이미지 200장을 280x280 으로 키운 그림과, 파이썬 전처리 결과, 예측 확률을 `../web_version/검증데이터.json` 에 담는다. 이 파일은 git 에 넣지 않는다.

### 전처리를 건드릴 때

캔버스 그림을 단순히 28x28 로 축소하면 인식률이 무너진다. MNIST 는 다음 규칙으로 만들어진 데이터이고, `mnist형식으로변환` 이 그 규칙을 그대로 재현한다.

1. 여백을 잘라내고 → 2. 비율 유지하며 20x20 에 맞추고 → 3. **밝기 무게중심을 28x28 한가운데로** 옮긴다.

세 단계 중 하나라도 빠지면 정확도가 크게 떨어진다. 바꿨다면 위에 적은 98% 검증을 반드시 다시 돌린다. **웹 버전의 `전처리.js` 도 같은 세 단계를 구현하고 있으므로 함께 고치고, `web_version/검증.html` 로 다시 확인한다.**

### 값이 중복된 곳

정규화 상수 `0.1307`, `0.3081` 이 **두 곳에 따로 적혀 있다.** 학습과 예측이 어긋나면 안 되므로 한쪽만 고치지 않는다.

- `train.py` 의 `transforms.Normalize`
- `preprocess.py` 의 `평균`, `표준편차`

웹 버전은 이 값을 직접 갖지 않는다. `가중치내보내기.py` 가 `preprocess.py` 에서 읽어 `가중치정보.json` 에 실어 보낸다.

### GUI 에서 알아 둘 점

- 캔버스에 그리는 동시에 **같은 내용을 PIL 이미지에 따라 그린다.** 화면 화소를 직접 읽는 방식은 운영체제마다 달라 신뢰할 수 없기 때문이다. `그리기시작`, `그리는중` 은 항상 두 곳에 같이 그려야 한다.
- PIL 의 `line` 은 선 끝을 둥글게 처리하지 않으므로 이음매마다 원을 덧그린다. 이 보정을 빼면 획이 각지게 남는다.
- `붓굵기 = 18` 은 280px 캔버스를 28px 로 줄였을 때 MNIST 획 굵기와 비슷해지도록 맞춘 값이다.
- `모델파일` 은 `Path(__file__).parent` 기준으로 찾는다. 파인더 더블클릭이나 앱 번들 실행에서는 현재 폴더가 달라지기 때문이다.
````

````markdown
## 구조

- **`모델.js`** — 가중치를 읽고 순전파를 수행한다. `../desktop_version/model.py` 의 구조를 손으로 옮긴 것이다.
- **`전처리.js`** — `../desktop_version/preprocess.py` 를 옮긴 것이다. **가장 깨지기 쉬운 부분이다.**
- **`그림판.js`** — 캔버스에 그리는 부분만 맡는다.
- **`앱.js`** — 위 셋을 엮어 화면에 결과를 표시한다.
- **`가중치.bin`, `가중치정보.json`** — 데스크톱 버전이 만들어 준 산출물이다. 이 폴더에서 직접 고치지 않는다.

## 파이썬 쪽과 동기화해야 하는 지점

이 폴더의 코드는 `../desktop_version/` 의 파이썬 코드를 손으로 옮긴 것이다. 아래 대응 관계가 깨지면 조용히 인식률만 떨어진다.

| 파이썬 | 자바스크립트 | 어긋나면 |
|---|---|---|
| `model.py` 의 층 구조 | `모델.js` 의 `예측하기` | 가중치를 잘못 해석해 결과가 전부 틀린다 |
| `preprocess.py` 의 3단계 | `전처리.js` 의 `mnist형식으로변환` | 인식률이 크게 떨어진다 |
| `app.py` 의 `붓굵기 = 18` | `앱.js` 의 `붓굵기` | 획 굵기가 학습 데이터와 달라진다 |

**가중치를 다시 학습했다면** `cd ../desktop_version && python3 가중치내보내기.py` 를 반드시 다시 돌린다. 그러지 않으면 웹 버전은 옛 가중치를 계속 쓴다.

정규화 상수 `0.1307`, `0.3081` 은 이 폴더 어디에도 적지 않는다. `가중치정보.json` 을 통해 파이썬에서 받아 쓴다. 값의 출처는 언제나 파이썬이다.

## 왜 ONNX 를 안 쓰나

원래 계획은 모델을 ONNX 로 변환해 ONNX Runtime Web 으로 돌리는 것이었다. 그런데 `onnx` 패키지가 표준 CPython 3.14 용 macOS 휠을 배포하지 않는다(free-threaded `cp314t` 용만 있다). 이 맥의 파이썬은 GIL 이 켜진 일반 빌드라 설치할 수 없다.

모델이 작아서(파라미터 42만 개, 순전파 430만 곱셈덧셈) 직접 구현이 오히려 단순했다. 외부 라이브러리가 0 개라 이 폴더를 통째로 정적 호스팅에 올릴 수 있다는 이점도 생겼다.

자세한 경위는 `../docs/superpowers/specs/2026-08-06-웹-데스크톱-버전-분리-design.md` 의 결정 5에 있다.

## 알아 둘 점

- 데스크톱 버전은 화면 캔버스와 PIL 이미지에 **같은 내용을 두 번** 그려야 했다. 브라우저는 `getImageData` 로 캔버스를 그대로 읽을 수 있어 한 번만 그린다.
- 포인터 이벤트를 써서 마우스와 터치를 같은 코드로 처리한다. 손가락으로 그릴 때 화면이 따라 스크롤되지 않도록 CSS 의 `touch-action: none` 이 필요하다. 이 줄을 지우면 모바일에서 그릴 수 없다.
- `전처리.js` 의 `파이썬반올림` 은 파이썬 `round` 와 같은 규칙(정확히 0.5 면 짝수 쪽)을 따른다. `Math.round` 로 바꾸면 드물게 무게중심이 한 화소 어긋난다.
- 캔버스 밝기는 R 채널만 읽는다. 검은 배경에 흰 글씨만 그리므로 R, G, B 가 항상 같기 때문이다. 색을 쓰게 되면 이 가정이 깨진다.
````

````markdown
## 두 버전의 관계

학습된 모델은 하나뿐이다. `desktop_version/` 이 `mnist_cnn.pt` 를 갖고, `가중치내보내기.py` 로 웹이 읽을 형식으로 풀어 준다.

```
desktop_version/mnist_cnn.pt
        │
        │  python3 가중치내보내기.py
        ▼
web_version/가중치.bin + 가중치정보.json
```

**학습을 다시 했다면 내보내기도 다시 돌려야 한다.** 그러지 않으면 웹 버전만 옛 가중치를 쓴다.

웹 버전의 `모델.js` 와 `전처리.js` 는 각각 `model.py` 와 `preprocess.py` 를 손으로 옮긴 것이다. 파이썬 쪽을 고치면 자바스크립트도 함께 고치고, `web_version/검증.html` 로 확인한다.

## 공통 규칙

- **식별자와 주석을 모두 한글로 쓴다.** 파이썬과 자바스크립트 모두 함수, 변수 이름이 한글이다. 예외는 셸 스크립트뿐이다. 셸은 변수 이름에 한글을 쓸 수 없다.
- **MNIST 전처리 세 단계를 지킨다.** 캔버스 그림을 그냥 28x28 로 줄이면 인식률이 무너진다. ① 여백을 잘라내고 ② 비율 유지하며 20x20 에 맞추고 ③ 밝기 무게중심을 28x28 한가운데로 옮긴다. 두 버전 모두 이 규칙을 구현하고 있다.
- **정규화 상수 `0.1307`, `0.3081` 의 출처는 언제나 파이썬이다.** 자바스크립트에 직접 적지 않는다.
- 테스트 프레임워크는 없다. 검증은 임시 스크립트와 `web_version/검증.html` 로 한다.
````
